# PC28 PPO Agent 实施计划

## 目标

在不推翻现有 WEB-PC 项目的基础上，增量接入 PPO 强化学习 Agent，形成：

`PC28 数据输入 -> 8 维状态 -> PPO 决策 -> 推理/执行风控 -> API 输出 -> 日志复盘`

## 最低验收标准

| 验收线 | 必须做到 | 不合格表现 | 处理方式 |
|---|---|---|---|
| 逻辑闭环 | 数据输入到 API 输出全链路可跑 | 数据断层、手填字段、重复下注、死循环 | 状态校验、期号去重、异常跳过 |
| 防爆底线 | 极端行情下 Agent 被 reward 教会认输；部署层有最后保险 | 越输越下、重仓硬抗、本金快速归零 | 训练靠惩罚，实盘靠 `risk_guard.py` 硬拦截 |
| 可落地性 | 独立 Python 子系统，少改现有项目 | 重构前端/API、依赖过重、改动范围失控 | 新增 `ai_agent/`，只接现有数据/API |

## 核心原则

| 原则 | 说明 |
|---|---|
| 环境不替 Agent 挡刀 | `casino_env.py` 只模拟输赢、资金变化、破产和 reward，不做连输强制跳过、低本金禁止下注等规则拦截 |
| 防爆规则不参与训练 | `risk_guard.py` 只在推理/执行层保护真实资金，不污染 Agent 学习过程 |
| 先看裸模型，再看部署表现 | 回测分两种：无风控裸跑、带 `risk_guard.py` 部署模拟 |
| 默认 dry-run | 未显式开启前，不触发真实下注 |

## 总体架构

| 链路 | 输入 | 处理 | 输出 | 合格线 |
|---|---|---|---|---|
| 历史数据层 | 已结构化开奖、遗漏、压力数据 | 清洗、补字段、生成训练样本 | 标准训练表 | 无缺列、无未来函数 |
| 环境层 | 每期样本 + 账户状态 | `CasinoEnv._get_obs()`、`step()` | observation、reward、done、info | `check_env` 通过，不拦截 Agent 动作 |
| 奖励层 | 单期动作、开奖结果、账户状态 | 计算赢、输、观望、破产惩罚 | reward 明细 | 错误决策会产生足够痛感 |
| 训练层 | `CasinoEnv` | SB3 PPO 训练 | `ppo_casino_model.zip` | 小样本训练可完成 |
| 回测层 | 历史数据 + 模型 | 裸跑/带风控两套回测 | 资金曲线、回撤、下注次数 | 能区分模型能力和部署保险 |
| 推理层 | 最新一期实时数据 | 加载模型预测动作 | 方向 + 金额比例 | 数据异常时跳过 |
| 风控层 | 推理动作 + 当前资金/API 状态 | `risk_guard.py` 做生产硬限制 | allow/deny/reason | 只保护实盘，不参与训练 |
| 执行层 | 风控通过的动作 | API payload + dry-run/实盘开关 | 下注 API 请求 | 不重复下注 |
| 日志层 | 每期输入、动作、风控、结果 | 记录审计日志 | JSONL 日志 | 可复盘每次决策 |

## 推荐文件结构

| 文件 | 作用 |
|---|---|
| `ai_agent/data_adapter.py` | 把现有 PC28 数据转训练表 |
| `ai_agent/casino_env.py` | Gymnasium 环境，只模拟市场和账户后果 |
| `ai_agent/reward.py` | 奖励函数，只把行为结果转成学习信号 |
| `ai_agent/risk_guard.py` | 推理/执行层防爆规则，不参与训练 |
| `ai_agent/train_ppo.py` | 本地训练脚本 |
| `ai_agent/backtest.py` | 历史回测脚本，支持裸模型和带风控两种模式 |
| `ai_agent/infer.py` | 单期推理脚本 |
| `ai_agent/executor.py` | 下注 API 执行，默认 dry-run |
| `ai_agent/config.py` | 参数、阈值、路径 |
| `ai_agent/logs/*.jsonl` | 决策审计日志 |

## 阶段计划

| 阶段 | 任务 | 新增/修改 | 输出物 | 验收 |
|---|---|---|---|---|
| 0. 现状审计 | 读取现有数据结构、脚本、API | 不改代码 | 接入点清单 | 确认数据源、下注 API、现有字段 |
| 1. 数据适配 | 转成 PPO 训练格式 | 新增 adapter | 标准 DataFrame | 每行具备 8 维状态所需字段 |
| 2. 环境实现 | 写 `CasinoEnv` | 新增 Python 模块 | Gymnasium 环境 | `reset/step/_get_obs` 跑通 |
| 3. 奖励机制 | 实现赢、输、观望、破产、极端错误惩罚 | 新增 `reward.py` | reward 明细 | 极端亏损会强惩罚，但不改动作 |
| 4. 训练脚本 | SB3 PPO + MPS 检测 | 新增训练脚本 | 模型 zip | 小步训练可完成 |
| 5. 裸模型回测 | 不加 `risk_guard.py` 跑历史 | 新增 backtest 模式 | 原始资金曲线 | 判断 Agent 是否真的学到 |
| 6. 部署回测 | 加 `risk_guard.py` 跑历史 | 扩展 backtest | 部署资金曲线 | 判断实盘保险效果 |
| 7. 推理脚本 | 读取最新一期并预测 | 新增 inference | action JSON | 无模型/无数据时安全退出 |
| 8. 风控执行 | 接 `risk_guard.py` 和下注 API | 新增 executor | payload + response | 默认 dry-run，显式开启才真投 |
| 9. 日志审计 | 每期记录输入、动作、reward、风控、错误 | 新增 logger | JSONL 日志 | 可追踪不下注原因 |
| 10. 构建验证 | 不破坏 WEB-PC | 运行 build/test | build 结果 | `npm run build` 不受影响 |

## 状态向量

| 序号 | 字段 | 含义 | 来源 |
|---|---|---|---|
| 1 | `current_omission` | 当前形态连续多少期未出 | 历史开奖/遗漏统计 |
| 2 | `pressure_score` | 当前盘口压力分 | 现有压力模型 |
| 3 | `cond_straight_rate` | 条件出顺率 | 历史条件概率 |
| 4 | `bot_win_rate` | 机器人非顺胜率 | 历史命中率统计 |
| 5 | `pressure_delta` | 当前压力分 - 上期压力分 | 压力序列 |
| 6 | `omission_avg_ratio` | 当前遗漏 / 历史平均遗漏 | 遗漏统计 |
| 7 | `window_density_100` | 近 100 期顺子比例 | 滚动窗口 |
| 8 | `relative_capital` | 当前余额 / 初始本金 | 环境账户状态 |

## 动作空间

第一版采用离散化金额，避免一开始自定义 PPO 策略网络：

| 维度 | 设计 |
|---|---|
| 方向 | `0=观望`、`1=买顺子`、`2=买非顺` |
| 金额 | `0-99` 档，映射到 `0.1% - 10%` 本金 |
| Gym 空间 | `MultiDiscrete([3, 100])` |

环境层接受 Agent 给出的动作并结算后果，不因为连输、低本金、高压力分而提前改写动作。

## 奖励机制

| 场景 | Reward |
|---|---|
| 下注赢 | `profit * ((100 - pressure_score) / 100)` |
| 下注输 | `abs(loss) * -5 * (1 + losing_streak)` |
| 大遗漏重仓输 | 在输钱惩罚基础上继续放大 |
| 观望 | `-0.01` |
| 资金破产 | 结束 episode，并给强负奖励 |

奖励机制只负责让 Agent 感受到后果，不负责替 Agent 跳过下注。

## 推理/执行防爆规则

这些规则只存在于 `risk_guard.py`，用于实盘最后保险，不进入 `CasinoEnv` 训练过程。

| 场景 | 规则 |
|---|---|
| 连输 2 次 | 最大真实下注比例减半 |
| 连输 3 次 | 实盘强制观望 1-3 期 |
| 本金低于 70% | 最大真实下注比例降到 2% |
| 本金低于 50% | 停止实盘，只允许模拟 |
| 压力分过高 | 禁止真实重仓 |
| 数据缺字段/过期 | 跳过本期 |
| 同一期已下注 | 拒绝重复执行 |
| API 异常 | 不重试重复下注，记录失败 |

## 技术取舍

| 点 | 方案 | 理由 |
|---|---|---|
| PPO 框架 | `stable-baselines3` | 成熟，不自造算法 |
| 环境框架 | `gymnasium` | SB3 推荐路线 |
| 动作空间 | `MultiDiscrete([3, 100])` | 最快跑通方向 + 金额 |
| 训练防爆 | reward 惩罚 | 让 Agent 自悟，不用脚本替它决策 |
| 实盘防爆 | `risk_guard.py` | 真实资金最后保险 |
| 真下注 | 默认关闭 | 避免误投 |
| 接入 WEB-PC | 增量目录 | 不推翻现有项目 |

## 第一版完成标准

| 项 | 标准 |
|---|---|
| 环境 | `CasinoEnv` 能加载历史数据并跑完整 episode |
| 训练 | 500-5000 步小训练能保存模型 |
| 裸回测 | 输出无风控资金曲线、最大回撤、下注次数 |
| 部署回测 | 输出带 `risk_guard.py` 的资金曲线和拦截原因 |
| 推理 | 给一条最新数据能输出方向、比例、是否下注 |
| 安全 | 默认 dry-run，不触发真实下注 |
| 项目 | 不删除数据，不重做现有功能，不影响 `npm run build` |

## 执行顺序

| 顺序 | 动作 |
|---|---|
| 1 | 读取 `git status`、`git diff`，确认不能覆盖现有改动 |
| 2 | 审计现有 PC28 历史数据、压力模型、下注 API |
| 3 | 新增 `ai_agent/` 最小闭环 |
| 4 | 先跑 dry-run + 小样本训练 |
| 5 | 跑裸模型回测，确认 Agent 本身是否学到 |
| 6 | 跑带 `risk_guard.py` 的部署回测 |
| 7 | 验证 `npm run build` |
| 8 | 通过后再考虑模拟盘或实盘开关 |
